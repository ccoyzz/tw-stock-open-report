# 台股開盤資料抓取器：設計文件

日期：2026-11-16
狀態：待使用者核准

## 1. 目的

使用者在 Claude chat 有一個每日排程任務「台股每日開盤統整」，交易日 09:40 產出報告。目前有兩個問題：

1. **開盤資訊不及時**：Claude 的網頁讀取工具被證交所即時報價擋住，只能等鉅亨網頁面更新。2026-11-16 的報告因此缺了 0050 與 00631L 的開盤價。
2. **游庭皓直播內容抓不到**：每天都回報「今日未取得直播內容」。

本專案做一支在 GitHub Actions 上每天自動執行的程式，把這兩類資料抓好、放到一個公開網址。Claude 排程任務改成讀這個網址，其餘（搜尋新聞、寫分析、送報告）照舊。

## 2. 已驗證的事實（2026-11-16 在 GitHub Actions 上實測）

- 證交所即時報價 `mis.twse.com.tw/stock/api/getStockInfo.jsp` 可連，一次回傳加權指數與三檔 ETF。欄位：`d` 日期（YYYYMMDD）、`o` 今開、`y` 昨收、`z` 最新成交（無成交時為 `-`）。
- 證交所 OpenAPI `STOCK_DAY_ALL` 可連，前日收盤與即時報價的昨收一致。
- YouTube 頻道 RSS 與頻道網頁在雲端拿不到影片清單。官方 YouTube Data API v3 可用。
- **原提示詞的頻道代號 `UCf0WClSgplv2lJ2X3OeI5YA` 是錯的**（指到一個沒有影片的頻道「Yuting Hao」）。正確的是 `UC0lbAQVpenvfA2QqzsRtL_g`。這是直播一直抓不到的根本原因。
- Gemini API（`gemini-flash-latest`）可以直接讀 YouTube 影片網址並整理內容。
- 儲存庫 Secrets 已有 `GEMINI_API_KEY` 與 `YOUTUBE_API_KEY`。

**尚未驗證**：直播檔剛可用時（約 09:15）Gemini 能否立刻讀取。實測是在直播結束數小時後。設計以重試加上明確的「未取得」狀態處理這個風險，第一個交易日上線後要觀察。

## 3. 目標、非目標、反目標

**目標**
- 交易日 09:02 前後，公開資料檔含四個標的的今開、昨收、漲跌、漲跌幅。
- 當天直播結束後，資料檔補上直播重點摘要與影片連結。
- 每一項資料都帶狀態與來源；拿不到就明確標示，不填猜測值。
- 休市日明確標示休市。

**非目標（這一版不做）**
- 美股收盤、新聞、匯率、三大法人、台指期夜盤：維持由 Claude 任務照現行方式處理。
- 寄信或推播：報告仍由 Claude 任務送出。
- 歷史資料查詢介面。

**反目標（出現就算失敗）**
- 資料檔裡出現舊日期的數字卻標成今天。
- 直播摘要是根據標題推測出來的內容。
- 金鑰出現在程式碼、資料檔或執行紀錄裡。

## 4. 考慮過的做法

| 做法 | 說明 | 取捨 |
|---|---|---|
| **一（採用）** | GitHub Actions 抓資料，現有 Claude 排程任務寫報告 | 報告品質與收件方式不變，免費；資料檔必須公開 |
| 二 | GitHub Actions 全包，Gemini 寫整份報告並寄送 | 不依賴 Claude；報告風格會變，要另設寄送管道 |
| 三 | GitHub Actions 抓資料，Claude API 寫報告 | 要另外付費 |
| （排除）Claude 雲端排程代理 | 測試時工作階段無法啟動，原因不明 |
| （排除）本機排程 | 使用者要雲端方案 |

使用者選擇做法一。

## 5. 架構

```
GitHub Actions（每個平日 08:30 台灣時間啟動）
  └─ python -m twopen.run
       ├─ 階段一：等到 09:00:30 → 查即時報價 → 寫出資料檔 → 推到 data 分支
       └─ 階段二：等直播結束 → Gemini 整理重點 → 更新資料檔 → 推到 data 分支

Claude 排程任務（09:40）
  └─ 讀 https://raw.githubusercontent.com/ccoyzz/tw-stock-open-report/data/latest.json
```

### 5.1 程式結構

Python 3.12，只用標準函式庫。

| 檔案 | 責任 |
|---|---|
| `twopen/quotes.py` | 查即時報價與 OpenAPI，回傳各標的的今開、昨收、資料日期；計算漲跌與漲跌幅 |
| `twopen/live.py` | 用 YouTube Data API 找當天直播影片並判斷是否已結束；呼叫 Gemini 產生摘要 |
| `twopen/report.py` | 把結果組成資料檔的結構，寫檔 |
| `twopen/http.py` | 共用的 HTTP 請求（逾時、重試；錯誤訊息不得包含網址，因為網址可能帶金鑰） |
| `twopen/run.py` | 進入點：安排兩個階段的等待與重試 |
| `tests/` | 用存好的回應樣本測試解析、計算、日期判斷；不連網路 |
| `.github/workflows/daily.yml` | 排程、執行、把資料檔推到 `data` 分支 |
| `docs/claude-task-prompt.md` | 給使用者貼回 Claude 排程任務的新版提示詞 |

測試階段的 `spike/` 與 `probe.yml` 在正式程式完成後刪除。

### 5.2 階段一：開盤數據

1. 等到台灣時間 09:00:30。
2. 查即時報價，標的：`tse_t00.tw`、`tse_0050.tw`、`tse_00631L.tw`、`tse_00685L.tw`。
3. 判斷：
   - 回傳的 `d` 不是今天 → 可能只是第一筆成交還沒進來，每 20 秒重查到 09:10。到時加權指數的 `d` 仍不是今天才視為休市：資料檔 `market_status = "closed"`，結束，不做階段二。
   - `d` 是今天但某標的 `o` 還是 `-` → 每 20 秒重查，最多到 09:10。到時仍沒有的標的標 `status = "missing"`。
4. 查 OpenAPI `STOCK_DAY_ALL` 取三檔 ETF 的官方前日收盤，與即時報價的 `y` 比對。不一致時兩個值都保留，並標 `prev_close_mismatch = true`。OpenAPI 失敗不影響主流程。
5. 漲跌 = 今開 − 昨收；漲跌幅 = 漲跌 ÷ 昨收 × 100，四捨五入到小數兩位。用 `decimal` 計算。
6. 寫出資料檔並推送。

### 5.3 階段二：直播重點

使用者提供的節目時間：直播為台灣時間 08:30–09:00，最晚 09:10 前結束，直播檔通常最晚 09:15 可用。因此預期摘要在 09:15–09:25 完成，趕得上 09:40 的報告。

1. 用 YouTube Data API 讀正確頻道的上傳清單（`playlistItems`，清單代號 `UU0lbAQVpenvfA2QqzsRtL_g`），找標題以今天日期開頭（格式 `YYYY/M/D` 或 `YYYY/MM/DD`）的影片。
2. 用 `videos.list`（`snippet,liveStreamingDetails`）確認直播已結束（有 `actualEndTime`，或 `liveBroadcastContent` 為 `none`）。
3. 還沒有影片或還沒結束 → 每 1 分鐘重查，最晚到 10:00（保留緩衝，應付直播延長或處理延遲）。
4. 結束後把影片網址交給 Gemini，請它用繁體中文、用自己的話整理：對美股、台股、總經、產業或個股的看法，以及提到的風險與觀察重點；只根據影片內容，不得推測。Gemini 失敗時每 2 分鐘重試，同樣最晚到 10:00。
5. 結果寫入資料檔並推送。狀態為下列之一：
   - `ok`：有摘要。
   - `title_only`：找到影片但拿不到內容，附標題、連結、影片說明文字。
   - `not_found`：到截止時間仍找不到當天影片。
6. 每次狀態改變都推送一次，讓 09:40 的 Claude 任務拿到當下最新的狀態。

### 5.4 資料檔 `latest.json`

```json
{
  "generated_at": "2026-11-16T09:01:12+08:00",
  "trade_date": "2026-11-16",
  "market_status": "open",
  "quotes": [
    {"name": "台灣加權指數", "code": "TAIEX", "status": "ok",
     "prev_close": "43675.12", "open": "43512.42",
     "change": "-162.70", "change_pct": "-0.37",
     "official_prev_close": null, "prev_close_mismatch": false,
     "source": "證交所即時報價"}
  ],
  "live": {
    "status": "ok",
    "title": "2026/11/16(一)…【早晨財經速解讀】",
    "url": "https://www.youtube.com/watch?v=…",
    "description": "…",
    "summary": "…",
    "updated_at": "2026-11-16T09:31:40+08:00"
  }

```

數字一律存成字串，避免浮點誤差。階段一完成時 `live.status` 為 `pending`。

### 5.5 排程與發佈

- 排程：平日 UTC 00:30（台灣 08:30）。GitHub Actions 排程常延遲數分鐘到數十分鐘，提早啟動、由程式自己等到 09:00:30 來吸收。若啟動時已超過 09:00:30 就立刻執行。
- 也可手動觸發（`workflow_dispatch`），方便測試。
- 工作上限 100 分鐘；正常情況約 09:25 前結束。
- 發佈：把 `latest.json` 提交到 `data` 分支，Claude 讀 raw 網址。該網址有約 5 分鐘快取，所以資料檔帶 `generated_at` 與 `live.updated_at`，讓 Claude 判斷新舊。

### 5.5.1 時區

使用者人在雪梨，股市在台灣。三個地方的時間各自獨立：

- **GitHub Actions 排程**：只認 UTC，與使用者所在地無關。台灣沒有日光節約時間，所以 UTC 00:30 永遠是台灣 08:30，不需要調整。
- **程式內部**：所有「今天」「09:00:30」「10:30」的判斷都明確使用 `Asia/Taipei`（`zoneinfo`），不得使用執行環境的本地時間。資料檔的時間戳一律帶 `+08:00`。
- **Claude 排程任務**：這是唯一受雪梨時間影響的地方，若它依使用者裝置的時區排程，設定時間要換算：

  | 期間 | 雪梨時區 | 台灣 09:40 等於雪梨 |
  |---|---|---|
  | 10 月第一個週日 ～ 4 月第一個週日 | AEDT（UTC+11） | 12:40 |
  | 4 月第一個週日 ～ 10 月第一個週日 | AEST（UTC+10） | 11:40 |

  雪梨每年切換日光節約時間兩次，屆時要手動把任務時間調一小時。新版提示詞會寫明「以台灣時間（Asia/Taipei）判斷今天的日期」，並用資料檔的 `trade_date` 把關，避免跨日誤判。

### 5.6 儲存庫改為公開（需要使用者同意）

理由有兩個：
- Claude 的網頁讀取工具讀不到私人儲存庫的檔案。
- 每天的工作可能執行超過一小時。私人儲存庫每月免費 2,000 分鐘不夠用，公開儲存庫不限。

公開後任何人都看得到程式碼、資料檔與執行紀錄。裡面只有公開行情與直播摘要。金鑰存在 Secrets，不會公開，GitHub 也會在紀錄中自動遮蔽。改公開前先刪除測試用的 `spike/`。

### 5.7 新版 Claude 提示詞

以使用者現有的提示詞為底，只改兩處：

- **第二段（直播）**：改成讀 `latest.json` 的 `live`。`ok` 時根據 `summary` 寫分析並附連結；`title_only`、`not_found`、`pending` 時照原規則寫「僅取得標題」或「今日未取得直播內容」。移除錯誤的頻道代號與 RSS 步驟。
- **第三段（開盤數據）**：改成讀 `latest.json` 的 `quotes`，並確認 `trade_date` 是今天。資料檔讀不到或日期不對時，退回原本的做法（中央社開盤新聞、鉅亨網）。

其餘段落不動。

## 6. 錯誤處理

- 每個外部來源獨立失敗：一個來源掛掉不影響其他項目，該項標 `missing` 並寫明原因（原因文字不含網址）。
- 程式任何情況下都要寫出資料檔。完全失敗時也要寫出帶今天日期與錯誤狀態的檔案，避免 Claude 讀到昨天的檔案卻以為是今天。
- Claude 端以 `trade_date` 把關。

## 7. 測試

- 單元測試（不連網）：即時報價回應解析、休市判斷、`-` 值處理、漲跌計算與四捨五入、標題日期比對（含個位數月日）、直播狀態判斷、資料檔結構。
- 上線驗證：手動觸發一次確認資料檔產出；下一個交易日早上觀察 09:02 的開盤數據與直播摘要完成時間。
